# Backup strategy

Single entry point for "what is backed up, how, and what is not". Written for a human
and for an AI agent: read this page first, then follow the links.

Last audit: 2026-09-12 (repo + live cluster + `jonbonas` shell). Re-audit when adding a
stateful app or a storage class, and at least twice a year.

## Legend

| Status | Meaning |
|---|---|
| ✅ covered | Automated, copy in a separate failure domain (offsite for class A), restore procedure written. A drill is recommended, not required: this is a homelab, and CNPG restores are a well-trodden path |
| 🟡 partial | Automated but missing one of: offsite copy for class A, sane retention, or the copy is on the same machine as the source |
| ❌ TODO | Irreplaceable data with no backup, work is planned |
| ⚪ accepted risk | No backup on purpose, the reason is written down |
| ♻️ rebuildable | Derived data (cache, index, metrics), regenerated by the app, no backup wanted |

"Physical" means a copy of the storage as the engine writes it (base backup + WAL, ZFS
snapshot, disk image). "Logical" means an export the engine can re-import (SQL dump,
`sqlite3 .backup`, tar of files). See [strategy.md](strategy.md) for why both matter.

## Where the copies physically are

| Location | Failure domain | Holds |
|---|---|---|
| Scaleway Object Storage `fr-par` | offsite, different provider | CNPG physical backups + WAL (`dixneuf19-cnpg-backups/physical/`), Terraform state, Burrito datastore |
| `jonbonas` `tank` (RAIDZ1, survives 1 disk) | same house, same rack | Immich library + Immich SQL dumps, Karakeep nightly tarballs, `nfs-jonbonas` PVCs |
| `jonbonas` `fastpool` (single NVMe) | same host, no redundancy | `k8s-worker-1` VM disk, so every `local-path` PVC on that node (Immich DB, Karakeep data) |
| `brassberry-25` USB disk (ext4, flaky) | single disk | every `nfs-client` PVC, cluster default storage class |
| `brassberry-27` USB disk (NTFS) | single disk | Videos, Prometheus TSDB |
| `brassberry-24` SSD | single disk | etcd |

Nothing today satisfies 3-2-1 for the photo library or for Karakeep. Only the two
Postgres databases have an offsite copy.

## How to use this folder

- New stateful app: read [strategy.md](strategy.md) (decision guide at the bottom), pick a
  techno page under `technos/`, reuse a tool from `tools/`, then add a row here and a page
  under `apps/` if the app owns irreplaceable data.
- Changing a backup: update the tool page and the recap row in the same PR.
- Restore drill done: fill the "Last restore test" column and the drill log in
  [strategy.md](strategy.md#restore-drill-log). Drills are worth doing for class A data,
  but a ✅ does not wait for one.
- Audit: for each 🟡 or ❌ row the gap must be named in the linked page, with either a
  TODO or an explicit acceptance.

## Folder layout

```
docs/backups/
  README.md          this page: recap table, locations, tools
  strategy.md        principles, tiers, physical vs logical, RPO/RTO targets, decision guide, drill log
  technos/           one page per data technology: what physical and logical mean for it, our rule
  tools/             one page per tool: how it is configured here, how to run and restore it
  apps/              one page per app holding real data: what, where, current backup, gaps
```
