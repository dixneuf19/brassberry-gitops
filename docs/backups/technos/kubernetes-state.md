# Kubernetes state

## Two kinds of state

| | Declarative (logical) | Runtime (physical) |
|---|---|---|
| What | Everything ArgoCD applies from this repo: 37 Applications, CRDs, ExternalSecrets | etcd content: generated Secrets, PV/PVC bindings, CNPG cluster status, Leases, certificates |
| Backup | git (GitHub) | `k0s backup` (etcd snapshot + certs + config) |
| Restore | bootstrap ArgoCD with two commands (README), wait | `k0s restore` on a fresh controller |

The cluster is meant to be rebuilt from git, and that mostly works. The exceptions are
listed below, and they are why an etcd backup still matters.

## Cluster facts

- k0s v1.34.3, **single controller** `brassberry-24` (Pi, `/var/lib/k0s/etcd`, 441M),
  4 workers. No etcd backup exists. `.gitignore` has `**/k0s_backup*`, so `k0sctl backup`
  was run by hand at least once.
- ArgoCD app-of-apps, `selfHeal` + `prune` on everything. Bootstrap is two manual
  commands in the repo README.

## Not reproducible from git

| Item | Where it lives | Impact if lost | Fix |
|---|---|---|---|
| `bws-machine-account-token` (ESO bootstrap) | Secret in `external-secrets` | no ExternalSecret can sync, every app blocked | recreate from Bitwarden machine account page (README) |
| CNPG app users `immich-app`, `spliit-app` | generated by CNPG | a restored cluster has the old password in `pg_authid`; the new Secret must be reset to match or the role password changed | after a physical recovery CNPG re-uses the backup's roles; set `bootstrap.recovery.secret` or `ALTER ROLE` |
| `argocd-secret`, `argocd-redis` | generated | sessions and webhooks invalidated, re-login | regenerate, re-add webhook secret (in Bitwarden) |
| cert-manager `issuer-account-key`, `*-tls` | generated | re-issue against Let's Encrypt rate limits (50 certs/week/domain) | wait or export the account key once |
| MetalLB `memberlist` | generated | regenerated at start | none |
| PV/PVC bindings for `Retain` NFS volumes | etcd | PVCs re-created by ArgoCD get new empty directories; old data stays on the NFS server under the old name | re-bind by hand or copy directories |
| `netflix/media-nfs` PV/PVC | applied by hand, chart dir not in `argocd/apps` | `files` stays Pending | apply `gitops/netflix/jellyfin/jellyfin-pv.yaml` |
| Loki, Promtail, Goldilocks | deployed out of GitOps | gone | re-apply from their dirs or drop them |
| `kube-proxy` ConfigMap edit | manual `kubectl edit` (documented) | metrics scrape breaks | redo per `gitops/kube-system/kube-proxy/README.md` |

## Restore order after total cluster loss

1. `make k0sctl` (or `k0s restore` if a backup exists).
2. Storage: `local-path`, `nfs-client`, `nfs-jonbonas` provisioners, then the static PVs.
3. `bws-machine-account-token` Secret, ESO, ClusterSecretStore.
4. ArgoCD bootstrap, let app-of-apps converge.
5. Databases: CNPG clusters bootstrap with `recovery` from the ObjectStores (edit the
   Cluster manifests before ArgoCD applies them, or apply them by hand first).
6. Files: restic restore into `/tank/media/immich`, Karakeep tarball into its PVC.
7. Re-bind or copy the `Retain` NFS directories for the small volumes.
