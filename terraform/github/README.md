# terraform/github

GitHub-side resources for brassberry-gitops: the burrito GitHub App installation
scope and the ArgoCD push webhook.

The provider authenticates with `GITHUB_TOKEN`, exported by the repo `.envrc`
from `gh auth token`.

## The burrito-brassberry GitHub App

GitHub has no API to create Apps, so the app itself cannot be a Terraform
resource. It is created once from the committed [`manifest.json`](manifest.json)
(name, permissions, events, webhook URL) via GitHub's app-manifest flow, and
everything downstream is IaC.

The app webhook is part of the manifest: deliveries for `push` and
`pull_request` go to `https://burrito.dixneuf19.fr/api/webhook`, authenticated
with a webhook secret generated by GitHub. No separate repo webhook is needed
for burrito.

### One-time setup

```bash
./create-app.sh
```

The script:

1. opens a browser form that POSTs `manifest.json` to GitHub (apps can only be
   created through a browser session)
2. asks for the `code` from the redirect URL
   (`https://burrito.dixneuf19.fr/manifest-redirect?code=...`, the page 404s,
   that is expected)
3. converts the code (`POST /app-manifests/{code}/conversions`) into the app
   credentials
4. stores `burrito-github-app-id`, `burrito-github-app-private-key` and
   `burrito-github-webhook-secret` in Bitwarden Secrets Manager

Then finish by hand:

1. Install the app on the single repo:
   `https://github.com/apps/burrito-brassberry/installations/new`
2. Copy the installation ID from the resulting URL
   (`https://github.com/settings/installations/<ID>`) and store it:
   `bws secret create burrito-github-app-installation-id <ID> <project-id>`
3. Adopt the 4 secrets in `terraform/bitwarden` (import blocks, see
   `terraform/bitwarden/github_app.tf`) and apply that root
4. `direnv reload`, then here:

```bash
terraform init
# the app was installed on the repo in step 1, adopt the binding:
terraform import github_app_installation_repository.burrito_brassberry_gitops <installation-id>:brassberry-gitops
terraform apply
```

### Rotation

Rotate the private key or webhook secret from the app settings page
(`https://github.com/settings/apps/burrito-brassberry`), then
`bws secret edit` the corresponding entry. ESO propagates within its refresh
interval.

## ArgoCD webhook

`github_repository_webhook.argocd` manages the pre-existing `push` webhook to
`https://argocd.dixneuf19.fr/api/webhook` and gives it a secret
(`argocd-github-webhook-secret`, auto-generated by `terraform/bitwarden` and
read here through its remote state). ArgoCD receives the same value through an
`ExternalSecret` merged into `argocd-secret`
(`gitops/argocd/argo-cd/templates/external-secret-webhook.yaml`).

Adopt the existing hook before the first apply:

```bash
terraform import github_repository_webhook.argocd brassberry-gitops/442446137
```

Apply order for the secret: `terraform/bitwarden` first (creates the secret),
then this root (sets it on the hook). ArgoCD accepts unsigned deliveries until
the ExternalSecret lands, so the rollout order does not matter cluster-side.
